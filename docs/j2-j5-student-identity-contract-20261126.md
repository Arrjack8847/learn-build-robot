# J2 → J5 student identity contract (private testing only)
## User decision
The user specified parent-email sign-in and then approved Option A (student ID + private PIN). Combined design: parent email + real OTP verification, select a student, enter that student's six-digit private PIN. Payer registration and payment remain separate from student access. No individual email required. Student PIN is provisioned only by an authorized payer for an owned student; reset is staff-assisted and requires a separate reviewed authorization flow. No reset endpoint in this increment. The email holder can still act as payer and provision an uninitialized PIN; do not claim stronger identity proof than the factors support.
## Implemented foundation
scripts/student-auth/identity.mjs: injected strong-store interface, role-specific enrollment and proof consumption, student-specific PIN attempt reservation (five attempts, 15-minute lock), separate four-hour student session with revocation/expiry and identity/ownership recheck. scripts/student-auth/crypto.mjs: private-preview-only dedicated secret, random salt, HMAC-peppered scrypt PIN, constant-time comparison, separate session digest domain. Tests are fixture-only. No route mounted, no real credentials or student rows created.
## J1 adapter requirements
New proposed admin-only collections (not created yet):
- StudentAuthCredentials: deterministic row ID = Children.childId, studentId, parentId, accountType, pinHash, credentialVersion, stateVersion, attempts (number), lockUntil (epoch milliseconds).
- StudentAuthSessions: deterministic row ID = sessionDigest, sessionDigest, accountType, studentId, parentId, credentialVersion, createdAt, expiresAt, revokedAt (epoch milliseconds or null), stateVersion.
Verify Wix uniqueness, consistent reads, conditional update/atomic CAS and server-only permission before enabling. Dedicated STUDENT_AUTH_SECRET in Preview only, generated in hosting settings; never in Git or browser. Student email OTP requires purpose-separated challenge and short-lived proof, bound to parent identity with atomic consume. Do not pass browser-supplied parent IDs; payer and student proof resolvers must be separate. Enrollment must use fresh verified payer authorization; no student-session elevation. Use separate __Host-bsr-student cookie (Secure, HttpOnly, SameSite=Strict, Path=/); never return raw token or PIN hash in JSON. Apply CSRF checks, per-IP/proof rate limit and body bounds before expensive PIN hashing. Explicit logout/switch must revoke prior student session, clear cookie and demand a new proof. Staff recovery, proof gateway, HTTP routes and UI remain unimplemented.
## J5 integration
Existing src/lib/wix-lms.ts obtains Wix member tokens and calls Wix directly; it is NOT compatible with this student session. Existing Children.childId must map one-to-one to StudentProfiles; coordinate authoritative mapping with J5/J1 before activation. J5 server handlers must derive studentId ONLY from resolveStudentSession(cookie), enforce membership and check-in independently, and use that ID for every profile/progress/quiz/challenge read/write. Never accept a browser-supplied student identity as authorization. Do not mint Wix OAuth tokens, auto-initialize a second profile, expose payer or staff permissions, or grant paid learning access from login. Keep existing J5 routes unchanged until migration is agreed and tested. Direct PDF/course origin security remains a J5 gate.
## Tests and release gates

No actual OTP proof, Wix persistence, browser sign-in, staff recovery, J3 payment or J5 profile integration verified by these tests. No production or company changes. Do not declare J2.8 complete.

## HTTP/UI increment
Added private-preview student-auth endpoints and normal /auth/ student email/PIN UI. Original Wix sign-in remains explicitly available via legacy=1 for J5 regression compatibility. Student sign-in remains disabled unless STUDENT_AUTH_ENABLED=true after verified dev-only schema and secret. Proof uses separate OTP identity namespace and five-minute cookie; proof is consumed with CAS; student login revokes any existing payer session on the browser. Payer enrollment requires a verified session created within ten minutes. Enrollment UI, proof-specific rate limiting, staff recovery and actual Wix verification remain pending. No J5 learning access enabled.

Parent registration now includes selected-student PIN enrollment with confirmation; pending security review, actual dev schema and live verification. Automatic Git deployments disabled on J2 branch only. Do not deploy until J2 implementation is ready. Other journey deployment settings unchanged.
