# J3 SGD authorized checkout — isolated development
Baseline 0dcd90cd53e08658d7f9f26f3119d95387ac731d. This module is not mounted; no provider calls or database writes were made.
The coordinator accepts only purpose, student ID, request key, and a booking ID for deposits. Server-derived session identity, verified consent, ownership, approved booking eligibility, and configuration are required. Only fictional example.invalid identities are permitted until J2 runtime integration. No parent dashboard is introduced.
The durable store must atomically check current entitlement and booking rules, reserve one unresolved attempt per student membership or booking deposit, enforce opaque reference uniqueness, and compare-and-bind provider IDs. A timeout, invalid URL or failed binding stays locked for reconciliation. A checkout return is not payment proof.
J2 provides the trusted session, current consent and parent/student ownership adapter. J1 provides preview-only rotated configuration and durable store. J4/J5 must consume verified membership status, never checkout status. No booking deposit policy is invented.
