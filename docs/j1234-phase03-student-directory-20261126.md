# Phase 03 — Registered student directory
Implemented independent HMAC-derived payer/student keys from an operator-provisioned 256-bit J1234_AUTH_ROOT, preserving existing J123 PINs and sessions. The exact new preview branch uses existing J2 registration/PIN handlers with isolated logical parent/child IDs and j1234-pin-v1- physical keys. J1234_TEST_EMAILS explicitly lists 1–5 approved controlled test inboxes; no inherited open-email mode. No additional staff login: platform preview protection and approved fictional dataset are the test boundary, not real staff authorization. Registration and student-directory flags require explicit enablement. Root and flags are not provisioned in this phase. The read-only directory derives exact parent IDs for approved inboxes and reads existing Children through strong parent-scoped queries; validates current consent, ownership, registration version and isolated PIN record. No duplication of registration or fixture data; search and pagination, direct canonical student filter, no raw payer, OTP or credential fields. The J1234 /staff/admin route displays registered students, refresh and PIN setup status; membership/check-in/learning deliberately unavailable, no false inactive/active status or fabricated progress. Standalone J4 UI/fixtures remain unchanged and unavailable on this branch. Phase 04 and 05 will extend this directory, not connect simulated actors to real records. No real provider or live email, database writes, deployment, production or J5 changes. Live acceptance deferred. Tests use injected fictional records and provider fixtures; no actual browser or Wix acceptance claimed.
