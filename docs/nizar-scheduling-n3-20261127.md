# N3 — Parent booking platform (private implementation)

Implemented server booking view, create, cancel, atomic reschedule; per-child one/day across activities, seven upcoming, independent capacity five, MYT operating hours and seven-day window, two-hour exact cancellation cutoff, membership and deposit authority interfaces, durable request fingerprints and replay, CAS retry, fail-closed uncertain commit. Bounded N2 aggregate remains pilot only. Full/elapsed slots are not selectable in UI. Existing bookings may be cancelled while unpaid; booking/move requires fresh active membership and clear deposit. No waitlist, reminders, penalties or actual payment integration in N3.

Independent fixture: /dev/nizar-booking and /api/dev/nizar/booking, exact Nizar branch, preview HTTPS host, explicit NIZAR_SCHEDULING_ENABLED=1 and NIZAR_FIXTURE_ENABLED=1 plus separate 64-hex operator key. Only three fictional students in two test families, one unpaid; no J2 cookie or real user identity accepted, no client payment overrides. Operator key stays in page memory, not browser storage. Uses previously provisioned Wix NizarSchedulingPreview collection; do not populate with real family data. UI is self-contained HTML/CSS/JS served by existing server to avoid a new auth/router dependency, not a production parent route. No external scripts. Actual parent UI identity/membership adapter will be connected to J2/J3 later; current service dependencies explicitly injected, no fake paid status for real students.
